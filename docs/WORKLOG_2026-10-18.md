# 工作日志（2026-10-18）

本文记录这一轮从"数据清洗 → 项目整合 → 环境打通 → 正式训练"的全部改动、原因和产物。按时间顺序写，便于复盘。

## 0. 任务背景

项目用 FG-CLIP2 做图片违规识别，重点是"文字扭曲、图片模糊"这类隐性违规。FG-CLIP2 本身只给图文相似度，工程上用 LoRA 微调视觉塔 + 四个分类头（risk / violence_type / injury / quality）产出结构化证据，再由 ReAct Agent 结合 OCR、RAG、低层像素工具和 LLM 给出最终建议。

本轮要解决四件事：数据配对清洗、标签头对齐、明显错误样本剔除、训练出第一版可用权重。

## 1. 数据配对与清洗

### 1.1 配对

原始导出 `project-6-at-2026-10-11-13-11-fa814d52.json` 共 3045 条任务，全部能在图片目录找到同名图片（0 缺图）。图片目录原有 3545 张，其中 **500 张没有任何标签引用**，已从工作目录删除（`D:\shujuji\6` 保留同一份备份）。删除后 `shujuji\6` 剩 3045 张，与 JSON 一一对应。

### 1.2 标签头对齐

训练标签文件只保留四个模型输出头：

- `risk_level`、`violence_type`、`injury_detail`、`quality`。
- `target`（敏感对象：人类/儿童/动物/无特定对象）和 `note`（标注员备注）不参与训练，剥离到 `review_extras.json`，避免敏感信息和自由文本进入训练文件。
- 所有取值归一化成 `src/labels.py` 的规范常量（例如 `L0_安全（无违规内容）` → `L0_安全`）。
- **quality 按多标签处理**：原始标注里存在 217 条同时命中多个质量标签的样本（如"严重模糊 + 文字扭曲形变"）。旧代码用单标签 `argmax`/取第一个匹配值，会直接把"文字扭曲"丢掉——这正是项目最关心的信号，因此必须改成 multi-hot + BCE。

### 1.3 确定性删除规则（最终版）

规则只处理"违规等级与表现字段互相排斥"的明显错误；一条样本命中多条时按优先级归因。

| 规则 | 含义 | 删除数 |
|---|---|---:|
| C1 | `violence_type` 同时选「无暴力」和其他暴力类型 | 3 |
| C2 | `L0_安全` 却标注直接暴力/后果展示 | 48 |
| C3 | `L0_安全` 却标注存在血腥 | 27 |
| C5 | `L0_安全` 却标注「暗示/威胁（武器指向/捆绑）」 | 19 |
| C4 | `L1/L2/L3` 却标注无暴力且无血腥 | 5 |
| C6 | `L1/L2/L3` 却缺失暴力类型或血腥程度 | 12 |
| C0 | 标注全部取消，无法训练 | 9 |

结果：**3045 → 2922，删除 123 条，通过率 95.96%**；其中任务三（确定性矛盾）114 条。C2/C3 有 3 条样本同时命中，所以规则命中次数为 130，按主因归类后正好加总为 114。

只进复核清单、不改标签的：`L0_安全` 却严重模糊/文字扭曲 **471 条**（按你的要求保留）。

### 1.4 数据侧遗留问题

保留样本中仍有 **106 条** `violence_type=无暴力` 但 `injury_detail` 有血腥（30 条为 L3）。它们不算"无违规表现"，所以按规则保留；但类型和血腥标注互相矛盾，建议下一轮标注重点复核。训练脚本每次会把这些列在"矛盾组合（供复核，未清洗）"里。

## 2. 代码改动

### 2.1 quality 多标签（核心）

改动的动机：单标签实现会静默丢标签，且 checkpoint 无法区分新旧语义。

| 文件 | 改动 |
|---|---|
| `src/labels.py` | quality 标注为多标签；`checkpoint_schema()` 写入 `schema_version: 2` 与 `task_types` |
| `src/dataset.py` | quality 用 `_encode_multihot`；新增 `quality_set` / `quality_valid`；无法映射或缺失时按缺失掩码处理 |
| `src/training_dataset.py` | batch 输出 `quality_target`（float multi-hot）+ `quality_valid` |
| `src/losses.py` | quality 改为 `WeightedBCE`，缺失样本不产生伪负标签 |
| `src/train.py` | quality 正样本频率权重；冒烟配置与产物隔离校验；可训练参数转 FP32 配合 GradScaler |
| `src/metrics.py` / `src/evaluate.py` | quality 用多标签指标（micro/macro F1 + 逐类 P/R/F1），按 `quality_valid` 过滤 |
| `src/engine.py` | quality 逐类 sigmoid + 阈值；阈值范围校验；拒绝旧单标签 quality checkpoint |
| `src/model.py` | head 按自身 device/dtype 接收 embedding；checkpoint 写 schema v2 |
| `backend/tools.py` / `backend/mock.py` | 证据文本、Mock 输出统一用 `quality.labels/scores/thresholds` |

推理侧效果：没有类别过阈值时返回空列表，不强制选一个；`文字扭曲 + 严重模糊`可以同时出现。

### 2.2 数据集构建工具（新增）

`src/build_dataset.py`：

- 按 `file_upload` 文件名配对，缺图/无有效标注剔除；
- 只保留四个输出头并归一化取值，`target/note` 写入 `review_extras.json`；
- 执行 C1–C6 删除规则，输出 `report.md` / `report.json` / `removed_samples.jsonl`；
- 重建时清理 `images/` 里已被剔除样本的旧图片（避免标签和图片数量不一致）。

输出目录：`data/clean/`（在 `.gitignore` 的 `/data/` 内，不会进 Git）。

### 2.3 死配置修复

`config/inference.yaml` 原来没有任何代码读取，quality 阈值也缺失。现在：

- `src/cli.py` 默认读取该文件，支持 `--config/--model-path/--ckpt-dir/--device/--no-lora` 覆盖；
- 文件补齐 quality 的 5 个阈值；
- `tests/test_inference_config.py` 校验阈值必须覆盖 `labels.py` 的全部类别且在 [0,1]，防止以后加类别时再次脱节。

### 2.4 兼容性与小修

- `tests/test_training.py` 使用 `contextlib.chdir`（Python 3.11+），在你的 Python 3.10 环境会报错，已改为兼容实现。
- `src/dataset.py` 的 textarea 备注按 `list[str]` 解析（否则备注会变成 `"['...']"` 字符串）。
- `.gitignore` 增加不带斜杠的 `/fg_clip`，避免软链接形式的模型目录显示为未跟踪文件。

## 5. 正式训练

配置：LoRA r=16/alpha=32/dropout=0.05，lr_lora=1e-4，lr_head=1e-3，weight_decay=0.01，AMP fp16，最多 20 epoch，patience 5，监控验证集 risk macro-F1。

唯一调整：`batch_size 16×1 → 4×4`，原因是 8GB 显存下 16 张图（多数 784 patch）同时前向/反向风险过高；4×4 保持有效 batch=16。

训练过程（验证集 macro-F1）：0.4459 → 0.4846 → 0.4942 → **0.5289（第 4 轮最佳）** → 0.5108 → 0.4831 → 0.5169 → 0.4955 → 0.5145，第 9 轮早停。总耗时约 14 分钟。

测试集（147 条）：

- risk：accuracy 0.7123，macro-F1 0.6215，L3 recall 0.8571。
- type：micro-F1 0.8224，macro-F1 0.7757（标定阈值后）。
- injury：accuracy 0.8116，macro-F1 0.4614。
- quality：micro-F1 0.5796，macro-F1 0.4556（标定阈值后）；文字扭曲 recall 0.929。

阈值标定：验证集逐类扫描，type 用 F1 最优；quality 中"文字扭曲"手工改为 0.25（召回优先）。结果写入 `config/inference.yaml` 与 `eval_results/threshold_calibration.json`。

```bash

wsl -d Ubuntu
conda activate fgclip
cd /mnt/d/Image-Review-Agent

# 测试

  --split val --test-split test --override "文字扭曲形变=0.25" \
  --out eval_results/threshold_calibration.json

# 单图推理
python -m src.cli --image data/clean/images/<某张图>.jpg
```
