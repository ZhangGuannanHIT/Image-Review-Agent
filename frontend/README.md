# ImageGuard 展示页与图片审核工作台

原生 HTML/CSS/JavaScript，无构建步骤。启动后端后访问 http://localhost:8000/；默认进入图片审核工作台，通过左上角 ImageGuard 或右上角说明弹窗进入同一文档内的项目展示页。直接打开 index.html 可以使用本地选图预览并浏览展示页，但不能提交审核请求。

展示页与工作台使用 `#home` 和 `#workspace` 切换，不重新加载文档。工作台右上角问号按钮提供简要使用说明，其中“查看项目概览”会打开展示页顶部；点击工作台左上角 ImageGuard 也可回到展示页。再次进入工作台时，页面内的图片和结果仍然保留。桌面端侧栏可完全收起，移动端使用覆盖式抽屉，展开/收起按钮提供随状态变化的悬浮说明。

## 使用流程

右侧初始展示说明。点击上传、将图片拖入右侧工作区，或直接粘贴剪贴板中的图片，确认预览后开始审核。工作区追加图片和等待状态，随后原样展示后端审核建议与编号。完成后可继续提交下一张，每次审核独立，不传递其他图片或结果，也没有文本输入。

左侧“工作区”列表可以新建分组、切换旧组。右键点击工作区，或点击该条目旁的“⋯”（适合触屏和键盘），可打开重命名和删除操作。重命名与删除确认均使用页面中央弹窗；删除当前或最后一个工作区后会自动切换或创建一个空工作区。每组分别保存自己的图片和审核结果，页面展示序号从每个工作区的 01 开始。“当前工作区的审核记录”旁数字是该组提交的图片张数。失败、取消或超时的记录保留并支持重新审核；重试更新该图片的显示结果，后端会生成新的审核编号。复制成功会在操作位置直接反馈。

## 留存与状态

- 各工作区及其图片 Blob、预览 URL、审核结果与提交时间仅存在页面内存中。
- 工作区编号和名称写入 localStorage，页面时间线、图片预览与展开状态只保留在当前标签页会话；刷新后工作区列表可恢复，但需要从各自持久化队列重新打开审核结果。
- “新建工作区”创建一个独立分组，每个分组拥有自己的自动审查区和已完成区，不与其他工作区共享队列。
- “清空页面工作区记录”只清空当前标签页的时间线，不删除 SQLite 队列；“清空队列”只删除当前工作区持久化记录和审计原图，不改变页面时间线。
- 点击右上角外观图标会展开三个中文选项：跟随系统、日间和夜间；当前选项具有明确的高亮状态。外观偏好写入本地浏览器，刷新后继续使用。
- 清空、换图和卸载时释放预览 URL。清空和取消会中止前端等待，后台任务及日志可能仍然存在。
- 每次只允许一个审核请求。新请求、取消与重置使用请求对象隔离，旧响应不会覆盖当前记录。
- 健康检查超时为 5 秒，审核等待超时为 120 秒。
- JPG/PNG/WEBP，单张不超过 10MB；后端校验为最终依据。
- Mock 标志固定显示在顶部，每条记录保留提交时的模式标记。

## 独立启动

通过本机 HTTP 静态服务独立启动前端时，在 `config.js` 的 `window.REVIEW_API_BASE` 中设置后端地址。后端允许 localhost 和 127.0.0.1 的 HTTP 前端跨端口访问。

## 接口

仅使用 GET /health 和 POST /api/review。审核上传字段为 image。成功响应保留
`id`、`suggestion`，并包含 `result`、四组 `groups` 和 `timing` 结构化证据；
错误响应读取 code、message、id。旧响应缺少结构化字段时回退展示建议文本。

结果页顶部固定展示程序动作、effective risk、risk raw、图片域、耗时和主要理由。
图片域统一为“真实”和“虚拟（二次元 / 插画 / 游戏场景等）”，风格路由和视觉复核也使用“虚拟”表述。
人工复核会额外显示“复核建议：建议限流/建议下架”及理由，但最终状态仍是人工复核。
耗时阶段、运营解释和完整 JSON 默认折叠。工具按 CLIP 基础头、专项模型与语境、
文字与规则、分支与最终裁决四组展示；每项同时标示执行状态和证据结论。
解释工具会标明结果来自程序模板、LLM 固定模板还是降级模板。

左侧持久化审核队列按 `workspace_id` 从 `/api/records` 读取，分为自动审查区和已完成区；已完成区
再分为通过和调整队列，可按真实/虚拟、最终动作和风险等级筛选。人工操作支持确认
和多次降级/升级调整，结果写入 SQLite；“导入文件夹”按自然排序逐张串行提交。
