# RAG 与前端实现说明

## 本次提交

- 前端：图片上传、拖拽和粘贴，工作区管理，结果复制、失败重试、取消、主题切换和移动端布局。
- RAG：将占位接口替换为本地规则与案例检索，使用 Python 标准库实现字符 n-gram TF-IDF 和余弦相似度，无额外模型或数据库。
- 接入：后端可直接提供前端页面；保留独立前端、可配置 API 地址和本机跨端口访问方式。

## 知识库与检索

`knowledge/knowledge.json` 包含 15 条规则、4 条核验案例、1 条教学案例。各条目包含来源、适用边界和反例。
`backend.rag.retrieve(query, k=5)` 返回规则或案例及相关度，默认最低相关度为 0.30。
相关度表示文本匹配程度，不是违规概率。反例只用于判断适用边界，不参与正向匹配。
来源核验状态随条目保留；教学案例不能作为权威判罚依据。

Agent 必须先成功调用 `analyze_image`，再按需调用 `search_knowledge`。
检索无命中不代表安全，命中规则也不代表必然违规；不能用检索内容补造图片事实。
RAG 提供辅助证据，最终建议由程序处置规则生成；视觉模型和血腥专项复核流程保持不变。

## 校准与测试

`knowledge/test_queries.json` 包含 55 条校准查询：15 条明确违规、15 条边界、15 条同义表达与 OCR 错字、10 条无关文本。
在这组查询上，Top-1 命中 44/45，Top-3 命中 45/45，无关查询拒绝 10/10，边界冲突 1/15。
这些查询参与了知识与阈值设计，不能作为独立测试集或实际图片审核准确率。

```bash
python -m unittest discover -s tests -v
node tests/frontend-flow.cjs
```

前端测试需要 Playwright 和本机 Edge，使用受控 API 响应验证交互，不代表真实模型效果。
前端记录只保留在页面内存，刷新后清空；主题与侧栏偏好可保存在浏览器。
后端原图留存继续由团队现有 `audit.save_images` 配置控制；RAG 查询以摘要缓存键记录，日志不保存 OCR 原文、完整知识正文或原始对话。

## 运行

按根目录 README 准备依赖、模型与 API 配置，启动 `python run_backend.py` 后访问 `http://127.0.0.1:8000/`。
运行模式由 `backend/config.yaml` 的 `runtime.mode` 指定，当前默认为 `real`。演示可设置环境变量 `BACKEND_MODE=mock`；Mock 结果仅用于流程联调。
独立前端仍可按 README 启动，并通过 `frontend/config.js` 设置后端地址。
密钥、本地配置、运行日志、ZIP 和生成截图不属于本次提交。
